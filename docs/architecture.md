# Architecture

Sortie is a single binary that talks to a remote server over SSH. There's no agent, no daemon, no control plane. Just a CLI that runs on your machine and a systemd service on the other end.

## Pipeline

```
CLI args → Config → Build → SSH Upload → Deploy → Health Check → Rollback
```

1. **CLI layer** parses subcommands and flags via `clap`
2. **Config** is read from `sortie.toml` (or auto-generated by `sortie init`)
3. **Build** runs `cargo build --release` with the target triple from config
4. **SSH transport** copies the binary to the server using the `ssh2` crate
5. **Deploy** stops the old systemd service, replaces the binary, restarts
6. **Health check** polls a TCP port until the service responds (or we give up)
7. **Rollback** restores the previous binary if health check fails

## Decision records

### Why raw TCP for health checks (no HTTP dependency)

The health check just opens a TCP connection to the configured port. If the connection succeeds, the service is up. This avoids pulling in an HTTP client library just to check if a port is open. If your app serves HTTP, a TCP connect tells you the listener is running. If you need to check a specific endpoint, you can wrap it in a shell command via the config.

### Why the ssh2 crate

We use `ssh2` (libssh2 bindings) instead of shelling out to the `ssh` command. This gives us proper error handling, session reuse, and SCP-based file transfer without parsing stdout. It also means Sortie works on Windows without needing OpenSSH installed.

### Why systemd

systemd is the default init system on every major Linux distro now. Using `systemctl` for service management means no extra dependencies on the server. The deploy step runs `systemctl stop`, copies the binary, then `systemctl start`. If you're not on systemd, you can override the restart command in config.

## File layout

```
pkg/cli.rs        # clap argument parsing
pkg/config.rs     # sortie.toml loading and validation
pkg/build.rs      # cargo build wrapper
pkg/ssh.rs        # SSH transport via ssh2 crate
pkg/deploy.rs     # deploy orchestration
pkg/health.rs     # TCP health check
pkg/rollback.rs   # version recovery
```
